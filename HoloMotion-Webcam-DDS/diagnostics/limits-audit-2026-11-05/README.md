# 侧平举、直臂与“你好”动作排查（2026-11-05）

本次只读检查在线状态和机器人配置，并独立运行理想骨架、IK、ONNX/MuJoCo。
没有修改生产限位、滤波、增益，没有向在线服务或机器人注入动作。

结论：这些现象有不同来源。已确认“你好”姿态存在 IK 分支选择失败；侧平举的
模型范围足够；直臂存在后续策略/动力学跟踪误差；骨架置信度门控会使整个参考冻结。
没有保存用户此次失败动作的逐帧三维骨架，不能认定现场每次失败的具体来源。

## 1. 侧平举没有被固定角度范围禁止

使用可见度 0.99、没有噪声的骨架，2 秒旋转抬臂后保持约 3–4 秒。
当前 IK 的侧平举上臂/前臂方向误差约 0.6°/0.8°，物理弯肘约 1.35°。
此时左肩 roll 约 89.6°，模型上限约 129°；肘电机约 82°，上限约 120°，
两者距离最近边界都约 38°以上。电机零点不等于人体关节角零点，伸直手臂不要求
G1 肘电机变成 180°。

取消 0.02 rad（1.15°）机械余量、关闭输入滤波、加迭代或放宽边界，都没有
实质改善这个侧平举结果。因此现场侧平举失败，不能先归为范围太窄。

完整理想骨架 → IK → 原 ONNX → 原 PD → MuJoCo 测试，三个动作各 300 步：

- 侧平举：没有跌倒。末帧上臂方向误差左/右约 1.4°/3.6°；肘仍弯约 7.5°/4.2°。
- 前伸直臂：IK 弯肘约 1.35°；物理输出仍弯约 14.0°/11.7°，前臂方向误差约 12.6°/9.6°。
- 当前 IK 的“你好”：在参考层已严重错误，进入策略/物理后也未完成目标。

这说明完全伸直的误差不能都归到摄像头或机械限位，也有策略/动力学跟踪误差。
以上是本次指定模型、增益、理想输入和六秒轨迹的结果，不代表所有姿态的跟踪能力。

## 2. “你好”存在明确的 IK 分支问题

测试目标：上臂侧平举，前臂向上。当前初值/迭代方式会选入不适合的弯肘分支：

- 左臂参考约为肩 pitch=-175.9°、roll=-89.9°、yaw=-94.2°、肘=118.9°。
- 多个轴顶到距离范围边界约 1.15°的位置，上臂方向偏差约 145°。
- 静态 MuJoCo 接触检查发现手臂与躯干、左右手臂之间严重穿插。
  原 IK 没有碰撞约束或“残差过大、贴边后重找解”的处理。

在完全相同的关节范围内，多初值求解可找到另一支解：
左臂约 pitch=-2°、roll=83°、yaw=94°、肘=-10°，准确满足目标。
将这支解只用作初值，再运行原生产 IK、原阻尼、原余量、原迭代次数，
前臂方向误差约 0.17°，上臂误差接近 0°；该静态模型姿态未检出手臂相关接触。

所以这个例子应修复求解分支选择和错误参考处理，而不是先扩大电机范围。
右图只证明静态模型存在可行解，不证明到达路径、平衡或实机表现。

![同一限位下的两种 IK 结果](hello-ik-branches.png)

过头直臂也有路径/分支影响：当前路径卡在肩 pitch 正向上限，约 26°上臂误差；
多初值在原范围内可降到约 5.3°，仍接近反向范围边界。此项确实同时涉及模型活动范围，
不应将离线放宽到 ±180°的结果作为实机参数建议。

## 3. 骨架与门控确实能造成“看着伸直却不伸直”及“没反应”

控制使用 MediaPipe 的三维 worldLandmarks；画面叠加使用二维 landmarks。
二维连线看起来笔直，不保证三维肩、肘、腕共线。

构造示例中，仅给肘点加入深度偏差，二维投影仍完全笔直：

- 肘深度偏差 4 cm：三维骨架已有约 17.5°弯肘，IK 约 17.8°。
- 肘深度偏差 8 cm：三维骨架已有约 34.2°弯肘，IK 约 34.5°。

这只是受控示例，不是测得当前摄像头有这些误差。

当前要求左右肩、肘、腕、髋八点全部 visibility ≥0.5。
只把一个腕点降到 0.49，就会先冻结完整参考约 0.25 秒，随后报“关键点持续不可靠”。
它不是单独停一只手；因此单侧遮挡可以造成两臂都没反应。
视频识别器还有 0.6 的检测/存在/跟踪门槛；无有效结果时不上传骨架，服务器在
0.5 秒接收超时后冻结。识别 FPS 或绿色二维骨架不能单独证明控制输入有效。

当前每臂只求肩三个轴加肘，腕参考保持默认。手掌方向和手指关键点没有用于 IK；
实验中只改变手部关键点，参考关节最大变化为 0。因此仅转腕或摆手不能直接映射。

## 4. 哪些是实机才额外施加的限制

机器人当前 arm_sdk 桥仅接管手臂并锁腰；肩肘 KP/KD=30/0.91，腕=30/0.91。
机器人桥 safety_scale=1，手臂范围与当前 MuJoCo 模型基本一致，并未额外大幅缩小。
前馈 YAML 默认关闭，但运行参数 `gravity.enabled=true` 覆盖为启用。

- 对齐命令每周期最多 0.005 rad，约 14.3°/s。
- 跟随发送每帧最多 0.02 rad；50 Hz 时约 57.3°/s，27 Hz 时约 30.9°/s。
- 机器人桥还做 3 rad/s 斜率限制及四点移动平均。
- 本机状态保护 0.5 秒，桥动作超时 100 ms；这些可导致实机等待或中断。

它们会叠加迟滞，但本次 IK 失败在不连接实机的离线环境已复现。
配置里的 35°上臂、30°肘弯、0.45 rad 站姿偏差是 strict 校准门槛；
当前纯仿真校准和冻结姿态实机对齐都走非 strict，不能把这些数当作运行幅度上限。

## 建议顺序

1. 修复 IK 多分支选择、贴边残差诊断及自碰撞参考拒绝；保持关节真实范围。
2. 同屏区分三维人体方向、IK 参考、策略物理姿态；记录每点可见度、残差、贴边轴。
3. 用理想直臂参考定位策略跟踪误差，再决定控制器或映射的调整。
4. 按实际骨架日志评估置信度策略；不要先整体降低阈值或关闭保护。
