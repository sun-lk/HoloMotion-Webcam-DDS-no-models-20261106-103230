## 结论

已确认左右手都在返回与 Dex3-1 对应的 7 关节状态，且机器人上有现成的三指手整机及独立手部 URDF。
当前 HoloMotion 摄像头链路仍指定橡胶手模型，没有将三指手质量与质心自动替换进来。
可见手臂桥代码将 tau 显式设为零，没有加载 URDF 进行重力前馈或在线负载辨识。

因此可以先利用现成模型进行静态重力核对，不需要从零测整套机器人 URDF。
但软件模型存在不等于该实物已被称重、辨识或完成精确修正；固件内部是否还有其它补偿也无法仅凭这些接口证明。

## 质量、安装与质心

整机三指手模型和两个独立手部模型，单手总质量均为 **0.69654599 kg**。
HoloMotion 标准 URDF 的橡胶手单侧为 **0.17 kg**，相差 **0.52654599 kg/侧**，约4.10倍。

两类手的模型安装位置相同：连接到对应 wrist_yaw_link，左侧 xyz=(0.0415, 0.003, 0) m，
右侧 xyz=(0.0415, -0.003, 0) m，rpy 均为零。
这确认了模型的安装坐标约定，尚未通过实物尺量核实转接件或额外附件。

以腕 yaw link 为坐标系，在保存的手指姿态下：

- 橡胶手质心约在 x=95.1 mm，y≈0，z=2.15 mm。
- 三指手左侧质心约为 (105.9, -9.4, -0.12) mm。
- 三指手右侧质心约为 (107.1, 9.5, -0.16) mm。

三指手质心随手指姿态变化。静态补偿应至少核对质量、质心及安装变换，不能仅把质量乘一个系数。

## 软件模型仍有不一致

独立与整机手部 URDF 的共同手指关节位置和转轴相同，左右手质量总和一致。
左手共同 link 惯性描述相同；右手掌 `right_hand_palm_link` 存在以下差异：

- 独立右手文件的 inertial origin rpy=(-1.57, 1.57, 0)。
- 整机文件的 inertial origin rpy=(0, 0, 0)。
- 两者掌部质量、质心 xyz 和原始惯量矩阵数值相同。

该区别会旋转惯量张量的表达方向，不能直接声称两份动态模型等价。
因为质量与质心相同，该项差异本身不会改变静态重力补偿。
本次没有根据猜测选定哪份惯量定义正确，动态前馈应先对齐 CAD/来源版本。

另有一个采样手指角 `left_hand_index_1_joint` 约 -1.801 rad，低于模型下限 -1.745 rad，
相差约3.2°。这可能涉及模型限位、关节零点或版本约定，不能仅凭此判断硬件故障。
离线 FK 使用原始读数，没有静默截断该角度；计算结果因此是带此约定限制的模型估计。

## 采样姿态下的静态重力差

`audit_models.py` 使用保存的身体关节、手指角和 IMU 姿态，分别对橡胶手和三指手整机 URDF
计算重力支撑力矩，比较两者之差。未考虑摩擦、回差、线缆力或运动加速度。

在该采样姿态下，差量绝对值大约为：

- 肩 pitch：左0.401、右0.435 N·m。
- 肩 roll：左0.466、右0.479 N·m。
- 肘：左0.578、右0.608 N·m。
- 腕 pitch：左0.323、右0.340 N·m。

精确正负号和全部关节结果见 `audit-result.json`。这些值不是固定补偿常数，换姿态必须重算。
程序用重力势能对关节角的数值差分核验解析计算，最大差异约1e-8 N·m。
这是计算实现自检，不是对实物模型准确性的实测验证。

4. 动态惯量前馈之前核实右手掌惯量坐标系和手指零点/限位约定。
