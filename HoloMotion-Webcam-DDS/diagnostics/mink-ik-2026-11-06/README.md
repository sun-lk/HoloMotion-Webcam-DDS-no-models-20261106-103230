# Mink 替换验证（2026-11-06）

范围：开发机的摄像头参考求解器；未启动实机服务或验证实机运动。

## 实现

- 固定 Mink 1.3.0、DAQP 0.10.3、qpsolvers 4.13.0；MuJoCo 3.17.0。
- 用肘、腕的位置任务替换旧自写 DLS，仍使用人体骨段方向和机器人臂长。
- 双臂仅 8 个肩肘自由度；其他自由度作为硬等式冻结。
- 机械限位及 0.02 rad 余量在 QP 内生效；保留参考滤波和平滑限速。
- 仅换成局部 QP 求解仍无法通过理想举手。增加三个固定初始姿态作为有条件恢复候选，
  所有候选都由 Mink 求解，不使用另一套自写数值 IK。
- 没有启用碰撞约束；固定分支恢复与限速不等于无碰撞路径规划。
- 没有调整 PD、重力前馈、HoloMotion 权重或机器人桥。

## 已执行

1. 55 项单元回归通过，约 9.1 秒。含理想侧平举、前伸、举手往返、逐帧限速和关节范围、
   错误/非有限 QP 不更新参考、模型副本隔离、冻结腕处于真实限位时仍可求解。
   日志：WSL `/tmp/holomotion-mink-unit-20261106.log`。
   明确排除 `test_integrated_dds.py`：它是导入即启动服务的独立 DDS 集成脚本，
   首次全目录发现时因未开启 CPU 放行而失败；DDS 集成不作为本次通过项。
2. `validate_mink.py`：3 个动作各 300 帧，20 Hz 理想输入、50 Hz 参考更新。
   侧平举和前伸上臂/前臂方向误差均小于 0.8°；举手均小于 0.2°。
   常规求解 P50 约 1.1 ms；举手含恢复的 P95 约 11.2 ms。
   最大参考角变化 0.05 rad/20 ms，与 2.5 rad/s 配置一致。
   详见 `reference-results.json`。
3. `validate_mink.py --policy`：真实 ONNX + 原模型 PD + MuJoCo 重力，3 个动作各 6 秒。
   都未触发骨盆低于 0.45 m 的跌倒判据，最低骨盆高度约 0.743 m。
   举手物理姿态最终方向误差约 3.9–8.7°；前伸前臂误差仍约 9.3–12.5°。
   这证明 IK 修正不等于策略精确跟踪。详见 `policy-results.json`。
4. `runtime_smoke.py`：专用 8766 direct 服务，合成 HTTP 骨架依次侧平举、举手。
   推进 492 步，最低骨盆高度 0.753 m，未跌倒，JPEG 渲染成功。
   最后暂停、清空摄像头序号并复位，服务留待人工调试。
   详见 `runtime-results.json` 和 `runtime-hello.jpg`。

三个固定候选并不保证任意动作全局可解，3 cm 触发阈值也不是精度保证。
上面的结果仅是指定理想骨架路径，未证明实际摄像头深度准确性、任意姿态避碰或实机稳定性。
